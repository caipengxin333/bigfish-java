## 判定证据与优先级

1. 读取失败先显示“暂时无法确认运行状态”，不使用过期成功信息。诊断只在 sessionId/state 同当前 runtime 时参与摘要。
2. 采集失败优先于随后播放断开及操作失败。FAILED 会话明确停止；若 collector FAILED 但 runtime 仍 RUNNING，则明确字段含义和未确认停止，不擅自宣称后端已停。CONNECTING、RECONNECTING、ENDED 分开说明影响。
3. 模型、合成、播放失败通过现有失败原因与同任务阶段轨迹归类；通用超时只有对应阶段轨迹或时间吻合的运行错误码时才定位。证据不足显示“任务处理失败/超时，无法确认环节”，不按事件类型、所选服务或 Token 状态猜测。
4. 使用 `lastFailure`、有限 `recent`、runtime 的 `lastError/lastErrorAt` 与各阶段成功时间。只把**同一环节、更晚**的成功当作恢复证据；同时间戳需有更大的该环节成功 sequence。较早成功、其他环节成功、目录检查、Token 可用、ready 均不清除失败。
5. 仍运行但未恢复的任务错误显示黄色“最近一次语音合成失败，互动仍在运行”等摘要与四步警示，不显示纯绿色等待，也不声称整个会话已停止。若本页同时未就绪，摘要说明播放影响，同时保留任务失败和未恢复证据。
6. 新的同环节成功后，错误成为折叠区历史记录；不声称原失败任务已重试。多个可见失败按环节判断，后一个环节恢复不会掩盖仍有证据的前一环节失败。
7. 礼物/关注/入场进入合成或播放的轨迹可说明模板正常处理；不能拿模板成功证明模型恢复。CONNECTED 仅说明连接，派发总数不声称真实评论或礼物分别通过验收。
8. 本页播放错误仅使用带当前 sessionId 的本地记录；就绪和实际播放分开。音频中断、租约到期、连接超时有具体提示；第二舞台占用时保持静音、不抢占。历史条目字段仅存在浏览器内，不发送到 WebSocket。
9. 原接口与请求字段不变：GET runtime/providers/bootstrap/config/diagnostics，POST sessions（三模式字段）及 stop、既有舞台协议。失败后继续由用户点击；恢复仍只接原会话，加载、保存、刷新、storage 同步均不启动。

摘要全部使用固定中文文案，不回显未知上游响应。测试也覆盖 URL形错误文本及 `constructor/__proto__/toString` 等异常键，避免泄露或渲染异常。原始安全错误码、Token、队列、会话编号及模拟工具仍在折叠区。
